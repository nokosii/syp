# 在地知識與文化治理

## 功能參考與在地化

參考 https://yuan-media-ai.vercel.app/ 的百科、AI 影像誌、雙向知識及工具入口，建置新楊平的地方主題百科、地方影像誌、雙向共學工作表及教學／田野模板工具。內容與圖像使用本系統原創示範，未重製參考站文章、圖像、GPT 或私有資料。

Two-Eyed Seeing 有其 Mi’kmaq 起源與文化脈絡。本站以「雙向共學」邀請地方生活經驗與研究證據對話，保留差異，不宣稱客家或桃園社群共享同一種文化方法。六個主題導讀是編輯的閱讀架構，不是新增田野事實。

## 協作流程

1. 課程前與居民／文化持有者共議記錄目的、命名、方法與不記錄事項。
2. 分別協商保存、公開、AI 處理、影音與再利用；保存同意的範圍及確認方式。編輯的勾選不能替代實際協商。
3. 提供原文、翻譯與影像供參與者回看；填寫社群範圍、可公開的文化脈絡與使用邊界。
4. 審閱者與社群確認用途，編輯登錄理由、時間與決定，另行確認 AI 檢索許可。
5. 將成果回到地方課堂與參與者，定期檢視用途；更正或撤回可經課程教師／知識庫管理員辦理。

參考 UNESCO 的社群參與清冊實務：https://ich.unesco.org/en/drawing-up-inventories-00313 。本站是一套可執行的保存流程，並非正式文化資產認定或完整法律合規審查。

## 已實作的權限

- 正式資料初始為 `editor / pending / ai_allowed=0`。新增與修訂只能存草稿。
- 原文、成果列表及附件共同要求：已發布、同意、公開權限、已審閱。操作示範另外明確標示。
- 搜尋（含關鍵字）另外要求 AI 許可；語意向量由同意 AI 處理後在本裝置建立。沒有 AI 許可仍可保存及公開閱讀原文。
- 同意 AI 檢索前檢查完整索引；缺少索引會回報如何重建。禁止向未允許 AI 處理的保存請求塞入向量。
- 修改原文或新增附件使公開與 AI 許可失效，重新審閱。時間版本比對阻止舊版本審閱覆寫新稿。
- 撤回即轉為草稿、僅編輯、撤回狀態、同意撤銷及 AI 許可關閉。再次使用必須重新確認同意與審閱。
- 生成回答前重新確認來源仍允許 AI 使用；已下載、截圖與外部引用無法由伺服器遠端回收。
- D1 保存建立、修訂前原文快照、審閱、附件與撤回紀錄。完整快照和審閱理由僅編輯可讀，公開頁只顯示可公開的社群脈絡及權限。
- 目前使用共用金鑰；紀錄的操作人為「編輯（共用金鑰）」，審閱者署名是填寫內容，不是個別帳號簽章，也不是獨立多人簽核。主系統仍維持原 Sites 存取範圍。
- 永久刪除成果會連同附件與治理紀錄刪除；保留與刪除期限由社群及管理員協議。

## GitHub 與主系統

GitHub Pages 為六份公開示範的靜態展示。百科、影像導讀、工作表下載與文件模板可運作；正式成果、私有資料、管理密鑰與治理快照不進入 bundle。新增正式成果不會自動同步至 GitHub。

共學工作表與工具箱草稿僅在本頁記憶體處理，重新整理清空，下載後由使用者保管；不是多人共編資料，也不會自動寄送電子報。RAG 保留現有來源引用及示範標記；尚未新增 ASR、TTS、OCR、自動影片分析、外部 GPT 代理或即時新聞爬取。


## 會員與六大庫共筆

簡報第 33 頁的三層工作空間落實為公開閱讀、課程共筆、查核治理。個別帳號登入申請後，管理員核准才能寫入。教師只讀寫自己建立或受邀的私有成果；審閱者查核全部成果並決定公開範圍；管理員負責成員角色、停用及維護。撤銷共筆或停用會員立即阻擋私有原文、附件與討論的讀寫。

六大庫的欄位、自由原文與來源一同保存。批次匯入預設不供 AI 處理，先核對後送審。共筆的版本比對會拒絕較舊保存，要求整合後再提交；邀請、送審、修改及審閱決定都有執行者署名。留言不會成為公開內容或檢索來源。使用者應避免在對外公開的欄位填入秘密或精確敏感地點；發布前由審閱者檢查全部欄位與附件。
